## 0. 확정된 것과 확인이 필요한 것

이 문서에서 가장 먼저 구분해야 할 부분이다. 섞어서 말하지 않는다.

| 구분 | 상태 |
|---|---|
| **지도 기반 = Google Maps** | **확정.** 사용자 결정 사항 |
| 대상 지역 = 서울특별시 | 확정 |
| 구체적인 3D 렌더 방식·SDK (Maps JS API의 3D Maps, Photorealistic 3D Tiles, Custom Overlay 중 무엇을 쓸지) | **확인 필요.** 공식 API 구현 확인 후 결정 |
| Map ID·API 키 | **미확보·미연동.** 기존 VWorld 키로 대체 불가 |
| 서울의 실사 지형·3D 건물 **커버리지와 정밀도** | **미검증.** 실제 API 연동 전에는 알 수 없음 |
| 분석용 정밀 표고(DEM/DSM/LiDAR) | 서울 전역분은 개방 목록상 **공개 제한**. 도로 지역분은 **목록상 공개이나 파일 미확보**(경로 탐색 중). 확보한 VWorld 90m DEM은 **거친 참고용** |
| 지형 차폐를 반영한 일조 계산 | **미구현** |

**Google Maps를 선택했다는 사실이 서울의 3D 지형·건물이 정밀하게 표시된다는 보장은 아니다.** 커버리지·품질은 연동해서 직접 확인한 뒤에만 기술한다.

GPT가 확인한 공식 문서: Maps JavaScript API 3D 개요 `https://developers.google.com/maps/documentation/javascript/3d/overview`, 고도 모드 `https://developers.google.com/maps/documentation/javascript/3d/altitude-modes`, 3D Tiles `https://developers.google.com/maps/documentation/tile/3d-tiles`. 이 외의 URL은 만들지 않는다.

## 1. 역할 분리 — 표현과 분석

이 프로젝트에서 지도와 데이터의 역할은 다음과 같이 **완전히 분리**한다.

| 역할 | 담당 | 내용 |
|---|---|---|
| **표현(렌더링)** | Google Maps | 지도 배경, 지형 기복, 3D 건물 등 **화면에 보여주는 부분** |
| **분석(계산)** | 내려받은 서울 공식 원본 자료 | 건물 형상·높이, 수목 위치·수고·수관, 표고(확보 시)를 **별도로 저장해 그늘·일사·지표를 계산** |

원칙:

- **Google 뷰어가 그리는 지형·건물 타일을 내려받거나 영구 저장해 분석에 쓴다고 가정하지 않는다.** 분석 입력은 공식 원천 자료(VWorld 건물, 서울 수목, 확보 시 DEM)에서만 온다.
- 화면에 보이는 Google의 3D 건물과, 우리가 계산에 쓰는 건물 형상은 **출처가 다른 별개 객체**다. 둘이 어긋나 보일 수 있으며, 그 사실을 화면에 표기한다.
- 계산 결과(그늘·등급)는 우리 데이터 기준이고, 배경 지도는 표현 수단이다. **배경이 정밀해 보인다고 계산이 정밀한 것이 아니다.**

## 2. 세 가지를 구분해서 진행

| 구분 | 내용 | 현재 |
|---|---|---|
| ① 지형 **표현** | 지도에 언덕 기복을 그리고 지물을 지면 높이에 맞춰 얹는 것 | Google Maps 기반으로 설계 중 |
| ② 지형 **차폐 계산** | 일조 엔진이 산·언덕에 의한 그림자를 실제로 판정하는 것 | **미구현. ①과 별개 작업** |
| ③ 지형 **자료 확보** | 분석용 DEM/DSM 실제 파일 | **미확보** |

**①을 했다고 ②가 된 것이 아니다.** 또한 **Google의 2D `TERRAIN` 지도 유형(음영기복이 그려진 평면 지도)과 실제 3D DEM 메시는 전혀 다른 것**이다. TERRAIN 지도 유형을 켠 것을 "고도 반영"이라고 쓰지 않는다.

## 4. 좌표·높이 기준 (먼저 고정할 것)

지형을 넣는 순간 **수평 좌표계**와 **수직 기준**을 동시에 관리해야 한다. 여기서 틀리면 건물이 땅에 파묻히거나 공중에 뜬다.

### 4.1 수평 CRS

- 건물 원천: **EPSG:5186**(투영, m 단위). 수목 원천: WGS84 지리좌표 표기(검사 중).
- Google Maps는 WGS84 위경도로 좌표를 받는다. 따라서 **표시용 변환 지점을 한 곳으로 모으고**, 거리·격자 계산은 투영좌표계에서 수행한다. 원천 CRS는 데이터에 함께 보존한다.

### 4.2 수직 기준 — 정표고와 타원체고

- 건물 자료의 높이는 보통 **지면으로부터의 상대 높이**, DEM 값은 **표고(절대)** 다. 성격이 다른 값을 그냥 더하지 않는다.
- 표고에도 **정표고(해발, 지오이드 기준)** 와 **타원체고(GNSS/WGS84 기준)** 가 있다. 한국에서 둘의 차이는 무시할 크기가 아니다.
- Google 3D 표시에는 고도 기준을 지정하는 **altitude mode** 개념이 있다(지면 기준/절대 기준 등). 어떤 모드가 어떤 기준을 쓰는지는 **공식 문서 확인 후 확정**하며, 확인 전에는 지물 높이를 지도에 올린 결과를 정확하다고 쓰지 않는다.
- 규칙: `표시 높이 = 지면 표고(기준 통일) + 지물 상대 높이`. 각 값의 기준을 메타데이터로 남긴다.

### 4.3 과장(exaggeration)

- 지형 **과장은 1로 고정**한다. 보기 좋게 부풀리면 그림자·경사 인식이 실제와 달라지고 발표에서 오해를 만든다.

## 5. 최종 설계 방향 — Google Maps 중심

### 5.1 기준 구성

```
[표현]  Google Maps (Maps JavaScript API)
         └ 배경 지도 / 지형 기복 / (가능할 경우) 3D 건물 타일
         └ 그 위에 우리 계산 결과 레이어를 올린다 (그늘·등급·격자)

[분석]  별도 저장한 서울 공식 원본
         └ 건물(EPSG:5186) · 수목(점+수고+수관) · 표고(확보 시)
         └ 태양 기하 + 차폐 계산 → 시간대별 일조/그늘 시계열 → 지표 A·B
```

### 5.2 확인 후 결정할 항목 (순서)

1. **어떤 3D 경로를 쓸 것인가** — Maps JavaScript API의 3D 지도 기능, Photorealistic 3D Tiles, 또는 2D 지도 + Custom Overlay 위에 자체 3D를 그리는 방식 중 선택. 공식 문서와 실제 동작 확인 후 결정한다.
2. **고도 모드** — 우리 계산 높이를 어느 기준으로 올릴지 확정.
3. **서울 커버리지** — 실사 3D·지형이 대상 구역에서 실제로 어느 수준인지 **연동해서 눈으로 확인**. 확인 전 결과를 전제로 설계를 굳히지 않는다.
4. **오버레이 정합** — 우리 격자·건물 결과가 Google 지형 위에서 어긋나지 않는지 시험.
5. **이용조건** — 타일 캐싱·저장·스크린샷·발표 사용 범위 확인. **뷰어 타일을 분석용으로 저장하지 않는다**는 원칙은 유지한다.

### 5.3 보조 비교안 (참고용, 채택 아님)

| 방식 | 비교 관점 |
|---|---|
| MapLibre + `raster-dem` 지형 | 기존 빛길 `app/`이 쓰던 스택. **레거시 출발점**으로서 코드 재사용 참고는 되지만 신규 기반으로 채택하지 않는다 |
| Cesium 계열 | 대용량 3D·terrain 처리 참고. 스택 교체 비용이 크고 이번 선택 대상이 아니다 |
| S-Map 등 서울시 3D 자료 | **분석용 표고·3D 자료 후보**로서의 가치는 별개로 남는다(표현 수단과 혼동하지 않는다) |

## 6. DSM 사용 시 중복 가산 금지

- DSM은 **건물·수목이 이미 포함된 표면 높이**다. DSM 위에 다시 건물 형상을 세우면 **높이가 두 번 더해진다.**
- 규칙: DEM(지면) + 건물 모델 조합, 또는 DSM 단독 사용 중 **하나만** 쓴다. 섞어 쓰는 구간은 격자 단위로 어느 소스를 썼는지 기록한다.
- 수목도 같다. DSM에 수관이 포함된 구간에 별도 수목 기하를 또 세우지 않는다.
- Google이 그리는 3D 건물 역시 **표현일 뿐이므로 분석 높이에 더하지 않는다.**

## 7. 표고 자료 확보 전/후 진행 범위

| 구분 | 표고 **미확보** 상태에서 가능 | 표고 확보 후 가능 |
|---|---|---|
| 건물 | 서울 건물 정제·높이 품질 검수·타일 준비, L0(건물만) 그림자 계산 | 지면 표고에 정합한 건물 배치 |
| 수목 | 수목 자료 정제(이상치·연도·구별 결측), 점 + 수고/수관 근사 기하 설계 | 지면 표고 위 수목 배치 |
| 지형 | 정밀 분석은 **불가**. VWorld 90m DEM은 거친 참고용일 뿐 골목 단위 계산에 쓰지 않는다. Google 지형은 표현이며 계산 입력이 아니다 | 지형 표현(①) 정합, 이어서 지형 차폐 계산(②) |
| 표기 | "지형 미반영" 명시, **경사·구릉 구간 판정 보류** | 반영 범위·기준 명시 |

- 표고가 늦어져도 건물·수목 작업은 병행할 수 있다. 다만 **지형 반영을 전제로 한 결과를 먼저 보여주지 않는다.**
- **도로 지역 DEM/DSM/LiDAR가 확보되면 중간 단계가 생긴다**: 도로·보도 구간만 정밀 표고를 적용하고, 도로 밖은 미확보로 남긴다. 이 경우 **적용 구간과 미적용 구간을 지도에서 구분 표시**한다.

## 8. 데이터 규모와 타일·LOD

- 서울 전체 건물은 manifest 기준 **695,754건**으로, 덕양구 63,882건(레거시)의 10배가 넘는다. 브라우저에 한 번에 올리는 방식은 성립하지 않는다.
- 진행 순서: **① 원천 정제·좌표 통일 → ② 타일/LOD 구조 결정 → ③ 시범영역에서 성능·정확도 확인 → ④ 서울 전역 확장.**
- 수목도 가로수 257,235 + 공원·사유지 178,390으로 대량이므로 점 심볼과 3D 기하의 표시 전환 기준(줌·거리)을 함께 정한다.
- 일조·그늘 계산 격자(레거시 기준 4m/10분)를 서울 전역에 그대로 적용할 수 없다. **계산 범위와 해상도는 시범영역에서 실측한 연산량을 근거로 결정한다.**

## 9. 시범영역

- **시범 자치구·구역을 임의로 확정하지 않는다.** 아래는 결정에 필요한 기준이며, 선정은 사용자 결정 사항이다.
- 고려 기준: 경사 변화 지역과 평지가 함께 포함되는가 / 가로수 자료 결측(가로수 자료에 종로구 없음)과 겹치지 않는가 / 건물 밀도 대비가 가능한가 / 현장 확인 접근성이 있는가 / 자료 최신성 편차가 큰 구간을 피할 수 있는가.

## 11. 남은 데이터·확인 부족 항목

1. **Google API 키·Map ID 미확보, 연동 없음.** VWorld 키로 대체 불가.
2. **서울 실사 지형·3D 건물 커버리지 미검증.** 연동 전 품질을 단정할 수 없음.
3. **정밀 표고 미확보.** 서울 전역 DEM 1m·DSM 1m·LiDAR·건물높이 공간정보는 개방 목록상 **공개 제한**. 도로 지역 DEM/DSM/LiDAR는 목록상 **공개이나 다운로드 경로 탐색 중**(파일 없음). 확보한 VWorld 90m DEM은 CC BY-NC-ND의 거친 참고용이며 정밀 분석 대체 불가.
4. **건물 높이 품질 미정리.** 양수 305,753건(43.9456%)뿐이고 0·음수 389,781건, 결측 220건. 최댓값 11,700m 이상치 검수 필요, 300m 초과 5건은 실제 초고층 가능성 때문에 일괄 제외 불가.
5. **수목 자료 최신성** — 2013년 자료, 종로구 가로수 결측, 수고 이상치(최대 1,911·1,313) 정제 기준 미정.
6. **수관 하단 높이·계절별 투과율** 자료 없음. 근사 가정으로만 가능.
7. **기상 자료** 미연동(03 문서 W01~W03).
8. **보행 도로망** 미확보(2차 범위 경로 기능 전제).
9. **현장 라벨** 없음. 모델 성능 주장 불가.

## 12. 레거시 구분

- 고양시 덕양구 건물 63,882건, CCTV 919개소 등 기존 산출물은 **레거시 참고 자료**다. `app/`과 기존 문서에 남아 있으나 **서울 대상 결과로 표시하지 않는다.**
- `app/`의 MapLibre/deck.gl 구성도 **레거시 출발점**이다. 계산 로직 재사용 참고는 가능하지만, **신규 기반 지도는 Google Maps로 확정**되었다.
- 서울 자료와 덕양 자료를 같은 표·같은 지도에서 합산하지 않는다. 화면·문서에 출처 지역을 항상 함께 표기한다.
