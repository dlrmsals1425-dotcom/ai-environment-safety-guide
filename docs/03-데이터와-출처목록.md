## 3. 기존 계산과 지도 서비스

- **SunCalc1.9.0**: 날짜·위치로 태양 방향/고도/일출일몰 계산. [해당 버전 공식 문서](https://raw.githubusercontent.com/mourner/suncalc/v1.9.0/README.md). 태양계산과 최종그늘·위험 예측의 오차를 구분한다.
- **MapLibre/deck.gl**: 기반 지도·3D표시. [MapLibre 지형 예제](https://maplibre.org/maplibre-gl-js/docs/examples/3d-terrain/)는 구현 참고이며 지형 데이터 공급원이 아니다.
- **VWorld 배경 타일**: 지도 이미지 설정과 지형 높이 연결은 별개다. 실제키는 신규 폴더에 없다.
- **OSM 배경 타일**: 기존 코드의 VWorld키 미설정시 대체 지도. 배경지도만으로 지형/나무 높이를 얻는 것은 아니다.
- **네이버 주소 조회**: 단건 임시 조회 기능 보존. 영구 CCTV 좌표 원천으로 사용하지 않음. 기상 기능과 무관.
- **UMEP**: [그늘 분석 매뉴얼](https://umep-docs.readthedocs.io/en/latest/processor/Solar%20Radiation%20Daily%20Shadow%20Pattern.html), [수목 모델 문서](https://umep-docs.readthedocs.io/en/latest/OtherManuals/SOLWEIG.html). 물리 분석의 참고/독립 비교 후보이며 현재 설치·연동되지 않음.

## 4. 통합 전에 확인할 항목

1. 좌표계·수직기준·단위 통일. 건물 ‘지면 위 높이’와 DEM ‘표고’를 구분한다.
2. DSM에 이미 들어있는 건물을 기존건물모델과 중복으로 더하지 않는다.
3. DEM/DSM의 격자간격과 수직정확도는 서로 다르다. 촘촘하게 보간해도 원자료 정확도가 높아지지는 않는다.
4. 나무의 계절·수관하단·투과율 고려. 자료 없는 나무를 실측 객체로 만들지 않는다.
5. 넓은 기상격자를 골목에 표시할 때 원래 해상도와 보간/추정 여부를 노출한다.
6. 평가 높이 선택: 보행자·CCTV·태양광 패널 위치에서의 그늘은 서로 다를 수 있다.
7. 촬영/갱신일과 분석시각 분리. 오래된 수목·철거 건물 등의 영향을 검토한다.
8. 지도에서 위험이 낮게 보이는 것과 데이터가 없는 것을 구분한다.

## 5. 다음 데이터 확보 순서(제안)

덕양구 시범구역 선정 → 기존 건물/CCTV 품질 확인 → DEM 확보 → 기상 실황·예보 연결 → 수목자료 가능성 조사 → 현장 라벨 수집 → 학습모델과 기준선 비교.
가능하면 수목이 많은 구간과 적은 구간, 경사와 평지를 함께 포함해 성능 차이를 확인한다.
자료가 없는 단계는 ‘계획/미확보’로 표시하고, 다운로드나 학습을 끝낸 것처럼 발표하지 않는다.
