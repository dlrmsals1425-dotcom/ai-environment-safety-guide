# 선제설 위험지점 연결 형식 v1

기상 원천 CSV/JSON과 **지도에 표시할 위험 산출 결과**는 다른 자료입니다. 이 형식은 후자의 연결 규약입니다. 현재는 파일 불러오기만 지원하며 서버 자동 수집/예측은 미연결입니다.

UTF-8 GeoJSON 파일(`.json`/`.geojson`), 최대 5MB·5,000지점. 한 파일은 동일 평가 작업의 지점별 스냅샷이며 지점 ID는 중복하지 않습니다. 같은 도로에 여러 예측 시각을 겹쳐 넣지 말고 조회 시각별 결과로 나눕니다. 좌표는 WGS84 `[경도, 위도]`입니다.

## 최상위 필드

| 필드 | 값/의미 |
|---|---|
| type | `FeatureCollection` |
| schemaVersion | 숫자 `1` |
| purpose | `operational` 또는 `test`. 테스트는 화면에 실제 위험이 아니라고 표시 |
| generatedAt | 시간대가 있는 ISO 8601 파일 생성시각 |
| source | 제공기관/분석 주체·자료명 |
| features | 아래 지점 Feature 배열 |

## 각 지점

`type: Feature`, `geometry.type: Point`, `geometry.coordinates: [경도, 위도]`.

properties 필드:

| 필드 | 요구사항 |
|---|---|
| id | 안정적인 지점/도로 구간 ID, 중복 불가 |
| name | 지점/도로 구간명 |
| level | `observed_ice`(결빙 확인 자료), `caution`(우려·추정), `insufficient`(판단 보류) |
| basis | `field_observation`, `screening_model`, `insufficient_data` |
| source | 이 지점 판단의 출처 |
| validFrom / validUntil | 시간대가 있는 ISO 8601. 시작 포함, 종료 미포함 |
| reasons | 설명 문자열 1~10개. 근거의 시각·값·단위·관측/예보 구분·원천 ID를 포함할 것 |
| modelVersion | caution이면 필수. 모델 또는 규칙의 버전 |
| inputKind | `observation`, `forecast`, `mixed`, `none` 중 하나. none은 자료 부족/판단 보류/quality missing인 경우만 허용 |
| quality | `good`, `suspect`, `bad`, `missing`. 원천 QC를 정규화한 제공자 상태. good 외에는 판단 보류 |
| observedAt | observation/mixed이면 필수. 시간대가 있는 실제 관측시각 |
| forecastIssuedAt / forecastValidAt | forecast/mixed이면 필수. 예보 발표와 대상시각을 분리 |
| spatialContext | 공간 대표성 설명 필수. 센서 위치/해당 지점만 대표, 입력 격자 해상도, 도로 구간 ID·길이, 관측소 거리 등을 알려진 만큼 명시 |

`observed_ice`는 `field_observation` 근거가 있어야 합니다. `caution`은 `screening_model`과 모델 버전이 필요합니다. 이 검사는 형식 검증이며 실제 현장 사실을 독립적으로 확인하는 절차는 아닙니다.

관측시각과 예보 발표시각은 파일 생성시각 이후이거나 유효기간 종료 이후일 수 없습니다. 유효기간 안에 새 관측이 들어오는 경우는 허용하지만, 선택 시각이 입력 자료 확보 시각보다 앞서면 판단 보류로 표시합니다. 예보 대상시각은 발표 이후이며 위험자료 유효기간 안이어야 합니다. 자료를 나중에 정리한 과거 스냅샷은 허용하지만, 과거 판단에 미래 관측을 섞지 않습니다.

초기 파일 연결 규약의 보수적 표시 한도는 **한 지점의 유효기간 최대 6시간**, **생성시각 대비 미래 범위와 예보 선행시간 최대 72시간**, **결빙 확인은 관측 기반·관측 후 최대 60분**입니다. 선택한 미래 시각을 관측 결빙 사실로 표시하지 않습니다. 이는 물리적 결빙 지속시간이나 공인 안전 기준이 아닙니다. 기간이 지난 자료를 안전으로 바꾸지 않고 판단 보류로 취급하기 위한 앱 정책이며, 실제 자료 제공 주기·지연을 확인한 후 버전 관리하여 조정합니다. 실제 자료의 생성시각이 PC 현재시각보다 5분 넘게 미래이면 거부합니다.

표시 원의 크기는 지점 위치를 찾기 위한 화면 기호이며 영향 반경이 아닙니다. 실제 도로 위험 구간을 표시하려면 이후 도로구간 ID/LineString과 구간 길이를 가진 별도 계약으로 확장합니다. 현재는 Point만 지원합니다. 오류 지점이 있으면 파일 전체를 거부하며 일부 지점만 누락한 지도를 성공 결과로 표시하지 않습니다.

선택한 날짜·시각이 유효기간 밖이면 원래 등급 대신 회색 **판단 보류**로 표시합니다. 과거 시각을 선택했을 때의 결과를 현재 위험 안내로 사용하면 안 됩니다. 서버에서 현재 자료 신선도·QC·공간 대표성을 먼저 검증해야 합니다.

## 점이 없는 형식 확인 예시

```json
{
  "type": "FeatureCollection",
  "schemaVersion": 1,
  "purpose": "test",
  "generatedAt": "2026-09-20T00:00:00+09:00",
  "source": "형식 확인용 — 실제 위험 자료 아님",
  "features": []
}
```

실제 관측하지 않은 지점을 예제로 만들어 운영 데이터에 넣지 않습니다. 기온만으로 만든 결빙 확정값이나 검증되지 않은 위험 점수를 주입하지 마세요. 기상청 제공 자료의 좌표·시각·단위·QC·공개 가능 범위는 별도 요청서를 따릅니다.

현재 불러온 파일은 브라우저 메모리에서만 처리하며 서버로 전송하거나 새로고침 후 저장하지 않습니다. 인증키, 개인 식별정보는 파일에 넣지 않습니다.

이 문서는 선제설 팀이 작성한 공개 연계 제안서로, 기상청 내부 문서나 실제 관측 자료를 포함하지 않습니다. 테스트 자료는 보라색 테두리와 테스트 문구로 운영 위험 표시와 구분합니다.
